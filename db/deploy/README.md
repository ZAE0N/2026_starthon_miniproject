# DB 서버 반영 스크립트

> **처음 하는 거라면 [GUIDE.md](GUIDE.md) 를 보세요.**
> Lightsail 인스턴스 생성부터 끝까지, 순서대로 따라가기만 하면 되게 써 뒀습니다.
> 이 문서는 각 스크립트가 무엇을 하는지 정리한 참고용입니다.

「DB 서버 반영 작업 지시서」 2부를 그대로 스크립트로 옮긴 것입니다.
**MySQL 이 하나도 안 깔린 빈 Ubuntu 서버**를 기준으로 만들었습니다.
**로컬 컴퓨터에서** 번호 순서대로 실행하세요.

## 준비

```bash
cd db/deploy
cp config.env.example config.env
```

`config.env` 를 열어 아래를 채웁니다.

| 항목 | 확인 방법 |
|---|---|
| `SERVER_IP` | Lightsail 콘솔 > 인스턴스 |
| `SSH_KEY` | Lightsail 콘솔 > 계정 > SSH 키 |
| `SSH_USER` | Ubuntu 이미지는 보통 `ubuntu` |

**비밀번호는 어느 파일에도 적지 않습니다.** 스크립트가 그때그때 물어보거나 직접 생성합니다.
`config.env` 와 `*.pem` 은 `.gitignore` 에 등록돼 있습니다.

## 실행 순서

번호가 지시서의 단계 번호와 그대로 맞습니다.

| 스크립트 | 하는 일 | 서버 변경 |
|---|---|---|
| `00-check-file.sh` | 덤프 파일 종류·문자셋·테이블 확인 | 없음 |
| `01-check-server.sh` | 접속·OS·디스크·메모리·MySQL 유무 | 없음 |
| `02-install-mysql.sh` | **스왑 → 설치 → utf8mb4 고정 → 보안 설정 → 검증** | **설치** |
| `03-upload.sh` | scp 전송 + 체크섬 검증 | 파일만 |
| `04-backup.sh` | 기존 DB 백업 | 없음 |
| `05-import.sh` | utf8mb4 로 임포트 | **DB 생성** |
| `06-verify.sh` | 검증 쿼리 8개 | 없음 |
| `07-appuser.sh` | 앱 전용 계정 생성 + 비밀번호 발급 | **계정 생성** |
| `08-network.sh` | bind-address, ufw | **설정 변경** |
| `09-test-remote.sh` | 로컬에서 원격 접속 테스트 | 없음 |
| `10-deploy-app.sh` | 프론트+API 배포 (nginx 단일 오리진) | **nginx·서비스 등록** |
| `reseed.sh` | (반복) 스키마·시드 다시 넣기 | **테이블 재생성** |
| `checksite.sh` | 배포된 사이트를 밖에서 점검 | 없음 |

`00` `01` `04` `06` `09` 는 읽기만 하므로 몇 번을 돌려도 안전합니다.
서버를 바꾸는 단계는 실행 전에 물어봅니다.

## 02 가 하는 일 (빈 서버 → 쓸 수 있는 MySQL)

1. **스왑** — RAM 1GB 미만이고 스왑이 없으면 2GB 스왑을 먼저 만듭니다.
   Lightsail 최소 사양(512MB)에서 스왑 없이 설치하면 중간에 죽습니다.
2. **설치** — `apt-get install mysql-server`.
   Ubuntu 22.04/24.04 기준 MySQL 8.0.3x 가 깔리므로 `CHECK` 제약 조건(8.0.16+)을 만족합니다.
3. **문자셋 고정** ★ — `/etc/mysql/mysql.conf.d/zz-inhatc.cnf` 를 만들어
   `character-set-server = utf8mb4`, `collation-server = utf8mb4_unicode_ci`,
   `default-time-zone = '+09:00'` 을 넣습니다.
   배포판 기본 파일은 건드리지 않고, 알파벳 순으로 뒤라서 이 값이 최종 적용됩니다.
4. **보안 설정** — `mysql_secure_installation` 이 대화형이라 쓰지 않고,
   같은 일을 SQL 로 처리합니다: 익명 사용자 제거 · `test` DB 제거 · root 원격 차단.
   **처리 후 실제로 그렇게 됐는지 다시 조회해서 확인합니다.**
5. **검증** — 버전이 8.0.16 이상인지, `sql_mode` 에 `STRICT_TRANS_TABLES` 가 있는지.

### 3번이 중요한 이유

팀원 덤프에는 `CHARSET` 선언이 한 줄도 없습니다.
그래서 테이블이 **서버 기본값**으로 만들어지는데, 이건 테이블 생성 시점에 박히고
나중에 고치려면 다시 임포트해야 합니다.

02 에서 서버 기본값을 `utf8mb4` 로 못 박아두면
**덤프 파일을 한 글자도 고치지 않고** 한글이 깨지지 않습니다.

### root 비밀번호를 만들지 않습니다

Ubuntu 의 MySQL 8 은 root 를 `auth_socket` 으로 만듭니다.
비밀번호가 아니라 "서버에 `sudo` 로 로그인한 사람인지"를 보고 통과시킵니다.

- 유출될 비밀번호가 애초에 없습니다
- 네트워크로 root 접속하는 방법이 아예 없습니다
- 서버 안에서는 `sudo mysql` 로 그냥 들어갑니다

지시서의 "root 비밀번호 설정"보다 안전해서 이대로 둡니다.
이후 스크립트도 전부 `sudo mysql` 을 씁니다.
**여기에 비밀번호를 걸면 `sudo mysql` 이 막혀 03~09 가 전부 동작하지 않습니다.**

## 안전 규칙

스크립트에 그대로 박아 넣은 제약입니다.

- 키 파일 경로와 비밀번호를 어떤 파일에도 쓰지 않습니다
- `root` 를 `'%'` 로 열지 않습니다 — `02` 가 처리하고 `07` 이 다시 확인합니다
- 3306 을 `0.0.0.0/0` 으로 열지 않습니다 — `08` 이 내 IP 로만 제한합니다
- 기존 DB 를 백업 없이 `DROP` 하지 않습니다 — `05` 가 백업 파일 존재를 확인합니다
- 배포판 설정 파일을 직접 고치지 않습니다 — 별도 파일(`zz-inhatc.cnf`)로 덮어씁니다
- 서버를 바꾸는 단계마다 확인을 받습니다

## 앱 배포 — 10-deploy-app.sh

프론트와 API 를 서버 한 곳에서 서빙합니다.

```
nginx :80
  ├─ /      →  /var/www/inhatc   (정적 파일)
  └─ /api/  →  127.0.0.1:8010    (uvicorn)
```

**같은 주소에서 나오는 것이 중요합니다.** GitHub Pages(`https`)에서 `http` 백엔드를
부르면 브라우저가 차단합니다(mixed content). 한 곳에서 서빙하면 그 문제도,
CORS 설정도 생기지 않고 링크도 하나로 끝납니다.

```bash
./10-deploy-app.sh
```

하는 일은 순서대로 이렇습니다.

1. `nginx` · `git` · `python3-venv` 설치 확인
2. 서버에서 저장소를 `git clone` (있으면 `git pull`)
3. `api/.env` 생성 — **DB 비밀번호와 OpenAI 키를 여기서 물어봅니다.**
   입력값은 이 컴퓨터에 저장되지 않고 서버로 바로 들어갑니다 (권한 600)
4. `venv` + 의존성 설치
5. **정적 파일만** `/var/www/inhatc` 로 복사
6. `uvicorn` 을 systemd 서비스로 등록 (재부팅 후 자동 기동)
7. nginx 설정과 재적용
8. 서버 내부에서 `/`, `/api/health`, `/api/notices`, 한글 확인

**코드를 고친 뒤 다시 실행하면 그대로 업데이트 배포가 됩니다.**

`main` 에 머지하는 것만으로는 서버가 바뀌지 않습니다. 서버는 배포할 때 받은
코드로 돌기 때문에, 반영하려면 이 스크립트를 다시 실행해야 합니다.

### 저장소 폴더를 통째로 서빙하지 않는 이유

`root` 를 클론 폴더로 잡으면 `db/seed.sql`, `api/.env`, `.git/` 까지 인터넷에
열립니다. `.env` 에는 DB 비밀번호와 OpenAI 키가 들어 있습니다.
그래서 화면에 필요한 것(`*.html` · `css/` · `js/`)만 골라서 복사합니다.

### 포트가 겹칠 때

백엔드는 기본으로 `8010` 을 씁니다. 서버에서 이미 그 포트를 쓰고 있다면
스크립트가 **점유 중인 프로그램을 보여주고 멈춥니다.** 그 프로그램을 끄지 말고
우리 쪽 포트를 옮기세요.

```bash
echo 'API_PORT=8020' >> config.env
./10-deploy-app.sh
```

nginx 가 `/api` 를 그 포트로 넘겨주므로 **접속 주소는 그대로**입니다.

점유 여부는 우리 서비스를 먼저 멈춘 뒤에 확인합니다. 프로세스 이름으로 구분하면
venv 의 uvicorn 이 `python3` 로 보여서 우리 것을 남의 것으로 오판하기 때문입니다.

### 마지막 한 단계는 콘솔에서

Lightsail 콘솔 → 인스턴스 → [네트워킹] → 규칙 추가 → **HTTP / 80**.
**여기는 IP 제한을 걸지 않습니다.** 심사위원이 접속해야 하므로 3306 과 반대입니다.

### 로그 보기

```bash
ssh -i <키> ubuntu@<서버IP> "sudo journalctl -u inhatc-api -f"
```

## 배포 확인 — checksite.sh

배포된 주소를 **바깥에서** 점검합니다. 심사위원이 접속하는 것과 같은 경로입니다.

```bash
bash checksite.sh http://<서버IP>
```

확인하는 것

- 화면 6개가 200 으로 열리는지
- API 건수 (공지 71 · 일정 33 · 문서 20) 와 한글
- **열려 있으면 안 되는 것** — `db/seed.sql` · `api/.env` · `.git/config` 이 404 인지
- **★ 챗봇 추천 질문 4개가 실제로 목록을 좁히는지** (action 과 근거 건수까지)
- 범위 밖 질문에는 목록이 안 바뀌는지

마지막에 통과/실패 개수를 냅니다. 시연 직전 리허설에 쓰세요.

## 데이터를 바꿀 때 — reseed.sh

최초 구축(00~09)이 끝난 뒤 데이터를 고치는 작업은 번호 없는 `reseed.sh` 로 합니다.

```bash
# 1. 데이터를 고칩니다 (단일 출처)
vi ../../js/data.js

# 2. seed.sql 을 다시 만듭니다
python3 ../tools/gen_seed.py

# 3. 서버에 적용합니다 (백업 → 전송 → 적용 → 건수·한글 확인)
./reseed.sh
```

**`js/data.js` 가 단일 출처입니다.** 프론트엔드의 목업 데이터가 곧 DB 시드라서,
한 곳만 고치면 화면과 DB가 같이 갱신됩니다. 백엔드가 죽었을 때 프론트가
목업으로 폴백해도 내용이 같습니다.

| 파일 | 내용 |
|---|---|
| `db/schema.sql` | 테이블 정의 — utf8mb4, CHECK 제약, chat_cache, 인덱스 |
| `db/seed.sql` | **자동 생성물.** 직접 고치지 마세요 |
| `db/tools/gen_seed.py` | `js/data.js` → `seed.sql` 변환기 |
| `db/dump_from_team.sql` | 팀원이 만든 최초 덤프 (기록용, 더는 쓰지 않음) |

현재 시드는 **공지 71 · 일정 33 · 문서 20** 건입니다.
팀원 덤프의 더미 데이터도 여기에 합쳐져 있습니다.

- 공지 5건은 전부 반영했습니다. 다만 `sub_category` 는 설계서상 `'근로'` 만
  유효하므로 `NULL` 로 정규화했습니다. 그대로 두면 `CHECK` 제약에 걸립니다
- 학사일정 5건은 프론트 일정과 전부 겹쳐서 제외했습니다. 넣으면 달력에
  같은 일정이 두 번 표시됩니다
- 문서는 `slug` 충돌을 피해 `vision`(교육목표 및 비전) 1건만 추가했습니다

## 문제가 생겼을 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `Permission denied (publickey)` | 키 파일 권한 | `01` 이 자동으로 `chmod 400` |
| 접속이 그냥 멈춤 (timeout) | 세 방화벽 중 하나 | `08` 의 ①②③ 모두 확인 |
| `Can't connect to MySQL server` | `bind-address` | `08` 의 ① |
| `Access denied for user` | 계정이 `@'localhost'` 로만 있음 | `07` 재실행 |
| `Authentication plugin ... ` | 클라이언트에 암호화 모듈 없음 | `pip install cryptography` |
| 한글이 `???` | 문자셋 | `02` 를 돌린 뒤 `05` 재실행 |
| 설치 중 서버가 멈춤 | 메모리 부족 | `02` 의 스왑 단계 |
| `CHECK` 제약이 안 걸림 | 8.0.16 미만 | 백엔드에서 값을 걸러야 함 |

## 끝난 뒤

`07` 이 출력한 `DATABASE_URL` 을 FastAPI 의 `.env` 에 넣습니다.
`?charset=utf8mb4` 를 빼면 한글이 물음표로 나옵니다.

프로젝트가 끝나면 반드시 정리하세요.

```sql
DROP USER 'inhatc_app'@'%';
```

그리고 Lightsail 콘솔에서 3306 규칙을 삭제합니다.
