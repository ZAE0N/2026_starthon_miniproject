# DB 서버 반영 스크립트

「DB 서버 반영 작업 지시서」 2부를 그대로 스크립트로 옮긴 것입니다.
**MySQL 이 하나도 안 깔린 빈 Ubuntu 서버**를 기준으로 만들었습니다.
**로컬 컴퓨터에서** 번호 순서대로 실행하세요.

## 준비

```bash
cd db/deploy
cp config.env.example config.env
```

`config.env` 를 열어 아래를 채웁니다.

| 항목 | 확인 방법 |
|---|---|
| `SERVER_IP` | Lightsail 콘솔 > 인스턴스 |
| `SSH_KEY` | Lightsail 콘솔 > 계정 > SSH 키 |
| `SSH_USER` | Ubuntu 이미지는 보통 `ubuntu` |

**비밀번호는 어느 파일에도 적지 않습니다.** 스크립트가 그때그때 물어보거나 직접 생성합니다.
`config.env` 와 `*.pem` 은 `.gitignore` 에 등록돼 있습니다.

## 실행 순서

번호가 지시서의 단계 번호와 그대로 맞습니다.

| 스크립트 | 하는 일 | 서버 변경 |
|---|---|---|
| `00-check-file.sh` | 덤프 파일 종류·문자셋·테이블 확인 | 없음 |
| `01-check-server.sh` | 접속·OS·디스크·메모리·MySQL 유무 | 없음 |
| `02-install-mysql.sh` | **스왑 → 설치 → utf8mb4 고정 → 보안 설정 → 검증** | **설치** |
| `03-upload.sh` | scp 전송 + 체크섬 검증 | 파일만 |
| `04-backup.sh` | 기존 DB 백업 | 없음 |
| `05-import.sh` | utf8mb4 로 임포트 | **DB 생성** |
| `06-verify.sh` | 검증 쿼리 8개 | 없음 |
| `07-appuser.sh` | 앱 전용 계정 생성 + 비밀번호 발급 | **계정 생성** |
| `08-network.sh` | bind-address, ufw | **설정 변경** |
| `09-test-remote.sh` | 로컬에서 원격 접속 테스트 | 없음 |

`00` `01` `04` `06` `09` 는 읽기만 하므로 몇 번을 돌려도 안전합니다.
서버를 바꾸는 단계는 실행 전에 물어봅니다.

## 02 가 하는 일 (빈 서버 → 쓸 수 있는 MySQL)

1. **스왑** — RAM 1GB 미만이고 스왑이 없으면 2GB 스왑을 먼저 만듭니다.
   Lightsail 최소 사양(512MB)에서 스왑 없이 설치하면 중간에 죽습니다.
2. **설치** — `apt-get install mysql-server`.
   Ubuntu 22.04/24.04 기준 MySQL 8.0.3x 가 깔리므로 `CHECK` 제약 조건(8.0.16+)을 만족합니다.
3. **문자셋 고정** ★ — `/etc/mysql/mysql.conf.d/zz-inhatc.cnf` 를 만들어
   `character-set-server = utf8mb4`, `collation-server = utf8mb4_unicode_ci`,
   `default-time-zone = '+09:00'` 을 넣습니다.
   배포판 기본 파일은 건드리지 않고, 알파벳 순으로 뒤라서 이 값이 최종 적용됩니다.
4. **보안 설정** — `mysql_secure_installation` 이 대화형이라 쓰지 않고,
   같은 일을 SQL 로 처리합니다: 익명 사용자 제거 · `test` DB 제거 · root 원격 차단.
   **처리 후 실제로 그렇게 됐는지 다시 조회해서 확인합니다.**
5. **검증** — 버전이 8.0.16 이상인지, `sql_mode` 에 `STRICT_TRANS_TABLES` 가 있는지.

### 3번이 중요한 이유

팀원 덤프에는 `CHARSET` 선언이 한 줄도 없습니다.
그래서 테이블이 **서버 기본값**으로 만들어지는데, 이건 테이블 생성 시점에 박히고
나중에 고치려면 다시 임포트해야 합니다.

02 에서 서버 기본값을 `utf8mb4` 로 못 박아두면
**덤프 파일을 한 글자도 고치지 않고** 한글이 깨지지 않습니다.

### root 비밀번호를 만들지 않습니다

Ubuntu 의 MySQL 8 은 root 를 `auth_socket` 으로 만듭니다.
비밀번호가 아니라 "서버에 `sudo` 로 로그인한 사람인지"를 보고 통과시킵니다.

- 유출될 비밀번호가 애초에 없습니다
- 네트워크로 root 접속하는 방법이 아예 없습니다
- 서버 안에서는 `sudo mysql` 로 그냥 들어갑니다

지시서의 "root 비밀번호 설정"보다 안전해서 이대로 둡니다.
이후 스크립트도 전부 `sudo mysql` 을 씁니다.
**여기에 비밀번호를 걸면 `sudo mysql` 이 막혀 03~09 가 전부 동작하지 않습니다.**

## 안전 규칙

스크립트에 그대로 박아 넣은 제약입니다.

- 키 파일 경로와 비밀번호를 어떤 파일에도 쓰지 않습니다
- `root` 를 `'%'` 로 열지 않습니다 — `02` 가 처리하고 `07` 이 다시 확인합니다
- 3306 을 `0.0.0.0/0` 으로 열지 않습니다 — `08` 이 내 IP 로만 제한합니다
- 기존 DB 를 백업 없이 `DROP` 하지 않습니다 — `05` 가 백업 파일 존재를 확인합니다
- 배포판 설정 파일을 직접 고치지 않습니다 — 별도 파일(`zz-inhatc.cnf`)로 덮어씁니다
- 서버를 바꾸는 단계마다 확인을 받습니다

## 문제가 생겼을 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `Permission denied (publickey)` | 키 파일 권한 | `01` 이 자동으로 `chmod 400` |
| 접속이 그냥 멈춤 (timeout) | 세 방화벽 중 하나 | `08` 의 ①②③ 모두 확인 |
| `Can't connect to MySQL server` | `bind-address` | `08` 의 ① |
| `Access denied for user` | 계정이 `@'localhost'` 로만 있음 | `07` 재실행 |
| `Authentication plugin ... ` | 클라이언트에 암호화 모듈 없음 | `pip install cryptography` |
| 한글이 `???` | 문자셋 | `02` 를 돌린 뒤 `05` 재실행 |
| 설치 중 서버가 멈춤 | 메모리 부족 | `02` 의 스왑 단계 |
| `CHECK` 제약이 안 걸림 | 8.0.16 미만 | 백엔드에서 값을 걸러야 함 |

## 끝난 뒤

`07` 이 출력한 `DATABASE_URL` 을 FastAPI 의 `.env` 에 넣습니다.
`?charset=utf8mb4` 를 빼면 한글이 물음표로 나옵니다.

프로젝트가 끝나면 반드시 정리하세요.

```sql
DROP USER 'inhatc_app'@'%';
```

그리고 Lightsail 콘솔에서 3306 규칙을 삭제합니다.
